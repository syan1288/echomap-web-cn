# 生图风格规则设置设计

日期：2026-11-19

## 目标

让用户在设置中查看并修改当前生图风格的默认规则，同时保留现有重新生成流程中的一次性补充指令。

## 明确边界

后端固定系统规则保持不变，不从前端传入，也不允许用户编辑或覆盖。固定规则继续负责：

- 保留建筑主体轮廓、屋顶、体块和地标识别度；
- 去除原照片背景、人物、车辆、天空、地面等非建筑内容；
- 保持独立建筑资产和建筑结构识别；
- 防止用户的风格要求把建筑改造成完全不同的对象。

用户只拥有风格规则的编辑权：

- 扁平插画风；
- 像素风；
- 水墨风；
- 治愈绘本风；
- 用户自定义风格；每个自定义风格都可以拥有独立名称。

## Prompt 数据流

生成请求由后端按以下顺序组合：

```text
后端固定系统规则
+ 用户当前保存的风格规则
+ 建筑名称或默认生成要求
+ 本次重新生成的临时补充指令（如果有）
```

第一次生成没有临时补充指令。第二次及后续重新生成可以从现有编辑输入框传入一次性补充指令，该指令不改变用户保存的风格规则。

对于 Gemini，固定建筑规则继续作为后端 `systemInstruction`。对于即梦和 ChatGPT Image 等没有同等 system role 的 provider，后端仍负责拼接固定规则，并明确其优先级；前端不能替换固定部分。

## 设置交互

设置页新增“生图风格”入口，显示当前默认风格。

进入后显示：

1. 风格列表：现有四种内置风格、已保存的自定义风格，以及“新建自定义风格”入口；
2. 选择某个风格后进入或打开编辑面板；
3. 编辑面板顶部是一行“风格名称”；
4. 主内容区是可输入的 `Prompt` 文本区域；
5. Prompt 区域右侧提供旋转箭头按钮，点击后恢复该风格的默认 prompt；
6. 面板右下角提供 `Cancel` / `Save`；
7. 可展开查看但不可编辑的“系统建筑规则”说明。

自定义风格编辑面板沿用当前项目已有的面板组件和视觉规范，不新增另一套弹窗样式。新建自定义风格时，用户填写名称和 prompt 后点击 `Save` 才写入列表；点击 `Cancel` 不产生保存结果。

自定义风格保存后：

- 出现在设置页的风格列表中；
- 出现在生图面板的风格选择器中；
- 可以被选择并用于下一次生成；
- 可以再次打开编辑；
- 可以删除，但删除前需要确认；
- 删除后不影响已经生成的历史建筑记录。

内置风格的名称不可修改、不可删除，但其默认 prompt 可以编辑，并可通过旋转箭头恢复内置默认值。

系统建筑规则只作为透明度说明，不提供编辑控件，也不随请求从客户端回传。

## 配置与持久化

第一版保存到当前设备的本地存储，并按登录用户标识隔离。数据至少包含：

```ts
{
  id: string;
  name: string;
  prompt: string;
  builtin: boolean;
}
```

未保存自定义内容时，使用代码中的内置默认风格规则。

需要避免用户配置污染已有建筑记录：历史建筑仍保留生成时的 `buildingStyle`，重新生成时读取当前设置中的对应风格规则。

## API 变化

生成请求增加可选的用户风格规则字段，例如：

```ts
{
  buildingStyle?: string;
  styleName?: string;
  stylePrompt?: string;
  userPrompt?: string;
}
```

后端对 `stylePrompt` 做长度限制和空值处理。后端始终使用自己的固定系统规则；缺少 `stylePrompt` 时回退到对应内置风格规则。自定义风格的名称和 prompt 属于客户端设置，不改变后端固定规则。

风格配置应集中在共享的风格定义中，避免设置页展示内容与后端默认内容分叉。固定系统规则仍只保留在后端。

## 安全与稳定性

- 不允许前端传入字段替换后端固定系统规则；
- 限制风格 prompt 长度，避免请求体膨胀和 413；
- 对用户输入做 trim；
- 保留现有 provider 的生成错误处理；
- 未配置自定义风格时必须与当前生成结果保持兼容；
- 用户点击“恢复默认”后立即回到当前内置规则。

## 验收标准

- 设置页可以选择四个现有风格；
- 每个风格可以查看并修改默认风格规则；
- 用户可以创建带名称的自定义风格；
- 自定义风格编辑面板包含名称、Prompt、恢复默认、Cancel、Save；
- Cancel 不保存修改，Save 后风格才出现在风格列表；
- 已保存的自定义风格会出现在生图面板的风格选择器中；
- 自定义风格可以再次编辑和删除；
- 修改后第一次生成使用修改后的风格规则；
- 重新生成时，临时补充指令会叠加，但不会永久修改风格规则；
- 后端固定建筑规则未被前端覆盖；
- Gemini、即梦、ChatGPT Image 三条路径都能接收同一套风格配置；
- 未做任何设置修改时，生成行为与当前版本一致；
- `stylePrompt` 过长时得到明确错误，而不是产生 413；
- 现有测试和构建通过。
